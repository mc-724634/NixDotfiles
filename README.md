# NixDotfiles

NixOS (flake) + Home Manager configuration for host `nixos`, user `mc`.
Hyprland + Dux Shell (DMS), fish + Ghostty, fully declarative.

## Layout

| Path | What it holds |
|---|---|
| `flake.nix` / `flake.lock` | Inputs (nixpkgs 26.05, Home Manager, Lanzaboote, Spicetify, Helium, nix-flatpak, Dux Shell, Dux Greeter, Bedrock-on-Linux) and the `nixos` system |
| `configuration.nix` | System: boot (Lanzaboote + TPM2 LUKS), hardware (AMD GPU/LACT/OpenRGB), networking, Hyprland + dms-greeter + DMS enablement, audio, services, system packages |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`; don't edit |
| `home.nix` | User packages, default apps, Spicetify (static Catppuccin Mauve), Vencord theme |
| `modules/hyprland.nix` | Seeds the Hyprland/DMS Lua config from `extras/hyprland/`, Qt platform theme (qt5ct/qt6ct), GTK theme/cursor fixups, notification sound theme |
| `modules/shell.nix` | fish (with the oh-my-zsh git aliases as abbreviations), Starship, Ghostty |
| `modules/fastfetch.nix` | fastfetch |
| `extras/hyprland/` | Vendored Hyprland Lua config (from a live `dms setup` run) - `hyprland.lua` plus `dms/*.lua` (binds, rules, animations, layout, colors, etc.) |
| `extras/fastfetch/` | fastfetch config |
| `extras/sounds/` | UI sound theme, installed to the XDG sound-theme path |

## Rebuild

```sh
sudo nixos-rebuild switch --flake .#nixos   # or `boot` to apply on next boot
```

New files must be `git add`ed before building (flakes only see tracked files).
Prefer `nixos-rebuild build` first to check the configuration evaluates and
builds before actually switching to it.

## Desktop: Hyprland + Dux Shell (DMS)

This replaced KDE Plasma (2026-11-22). Dux Shell (formerly "DankMaterialShell")
is a Quickshell-based desktop shell; its own flake (`dux-shell` input) ships a
version-matched package + Home Manager/NixOS module pair, used instead of
nixpkgs' bundled (and older-pinned) `programs.dms-shell`.

- **Login screen**: `dms-greeter` (`dux-greeter` input, `programs.dms-greeter`
  in `configuration.nix`), a greetd-backed greeter that runs in the same
  Hyprland compositor as the real session and syncs the logged-in user's
  wallpaper/colors/cursor theme (via `configHome`). Needs any theme it should
  pick up (e.g. `bibata-cursors`) in `environment.systemPackages`, not just
  the user's home-manager profile - the greeter runs as a separate `greeter`
  system user that can't see the latter.
- **Hyprland config is Lua**, not the classic `hyprland.conf` syntax, and is
  **seeded, not continuously managed** by Home Manager (`modules/hyprland.nix`'s
  `seedHyprlandConfig` activation script copies `extras/hyprland/**` into
  `~/.config/hypr/` only if the destination doesn't already exist). This is
  deliberate: DMS and its own tooling live-edit several of these files after
  the initial seed -
  - `dms/colors.lua` is rewritten by DMS's matugen wallpaper hook on every
    wallpaper change.
  - `dms/binds-user.lua` is rewritten **wholesale** by DMS's in-app keybind
    editor on every save, keeping only `hl.bind`/`hl.unbind` lines and
    silently dropping anything else that used to live there.
  - `hyprland.lua`'s `DMS_STARTUP_BEGIN`/`END` block is managed by DMS's own
    `dms setup`/deploy tooling.

  Any non-keybind customization (polkit autostart, Qt platform theme
  overrides, monitor/workspace rules, `follow_mouse`, etc.) therefore lives in
  `dms/user-config.lua` instead - a file none of DMS's own tooling touches,
  loaded last in `hyprland.lua`'s `require` chain so its `hl.env`/`hl.config`
  calls win over whatever came before.
- **Theming is DMS-owned, not Nix-owned.** Cursor theme, icon theme, and sound
  theme are picked through DMS's own settings app (which writes its own
  `settings.json`/profile files), not `home.pointerCursor`/`gtk.enable` -
  letting Home Manager manage those files wholesale would fight DMS on every
  rebuild. Nix's job is just to make the packages *available* (`home.packages`
  in `modules/hyprland.nix`), plus a couple of narrow, confirmed gaps DMS
  itself doesn't cover:
  - GTK apps don't pick up DMS's cursor pick from `settings.ini` on their own
    (`home.activation.fixGtkTheme`).
  - GTK3's own fallback Adwaita theme uses legacy CSS variable names that
    DMS's color overrides don't target - `adw-gtk3` (a GTK3 theme built for
    the newer names) plus a `dconf` write are what make GTK3 apps (Thunar,
    etc.) actually show DMS's live colors.
- **Qt apps** use qt5ct/qt6ct (`qt.platformTheme.name = "qtct"` in
  `modules/hyprland.nix`), which is where DMS's matugen hook writes live Qt
  colors - not the `gtk3` platform theme bridge, which doesn't pick up DMS's
  colors at all. `hyprland.lua`'s own generated startup block hardcodes both
  `QT_QPA_PLATFORMTHEME` and `QT_QPA_PLATFORMTHEME_QT6` to `gtk3`; both are
  overridden back to `qt5ct`/`qt6ct` in `dms/user-config.lua` since that file
  loads after Hyprland's own startup env-setting and wins for every process
  Hyprland spawns.
- DMS itself runs as its own systemd user service
  (`programs.dank-material-shell.systemd.enable = true` in
  `configuration.nix`), not via an `exec-once`/`hl.exec_cmd` hook in
  `hyprland.lua` - it gets auto-restart-on-crash and ordering before
  `tray.target` for free. `hyprland.lua`'s `DMS_STARTUP` block used to also
  launch DMS via `hl.exec_cmd("dms run")`; that line was removed once the
  systemd service took over, since leaving both active would race two
  processes for the same D-Bus name (`org.freedesktop.Notifications`) and one
  would lose. If a future `dms setup`/deploy run ever regenerates that exec
  line, remove it again (or flip `systemd.enable` back to `false`) rather than
  running both.

## Notes

- `extras/hyprland/dms/binds.lua` and `windowrules.lua` are DMS defaults,
  vendored verbatim from a live `dms setup headless --compositor hyprland
  --terminal ghostty --no-systemd` run - don't hand-edit them, they're
  overwritten by DMS's own tooling. Put overrides in `binds-user.lua`
  (keybinds) or `user-config.lua` (everything else).
- Flatpaks are declarative (`services.flatpak` in `configuration.nix`, via the
  `nix-flatpak` input): the app list there is the full source of truth, kept
  in sync on every rebuild. `uninstallUnmanaged = true` means any app
  installed by hand with `flatpak install` gets removed on the next
  `nixos-rebuild switch` - add it to `services.flatpak.packages` instead.
  `flathub` is the only remote.
- PipeWire's `module-x11-bell` (the old X11 system-bell-to-sound bridge)
  crashes the whole PipeWire server on an X11/XWayland I/O error, silently
  killing event sounds for the rest of the session even after PipeWire itself
  recovers. `configuration.nix` disables the module entirely via
  `services.pipewire.extraConfig.pipewire`, since it's only the legacy bell
  beep.
- Minecraft Bedrock comes from the `bedrock-on-linux` input. It deliberately
  does **not** follow our nixpkgs: it is written for nixos-unstable and fails
  to evaluate on 26.05. Update it with `nix flake update bedrock-on-linux`.
- `boot.kernelParams`' `amdgpu.ppfeaturemask=0xffff7fff` clears the
  `PP_GFXOFF_MASK` bit of the LACT-required `0xffffffff` default, forcing
  GFXOFF off - without it this RX 6600 XT spams "Failed to disable gfxoff!"
  in dmesg. Keep until nixpkgs/amdgpu ships a real fix for the underlying SMU
  race.
- Monitor brightness sliders use DDC/CI (`ddcutil`/`hardware.i2c.enable`); the
  monitor must have DDC/CI enabled in its on-screen menu.
- Both `valent` (Home Manager) and `programs.kdeconnect` (NixOS, KDE Connect
  protocol/ports) implement the KDE Connect protocol side by side - not a
  conflict Nix resolves, just something to be aware of if phone pairing acts
  up (only one is likely to hold the discovery port at a time).
