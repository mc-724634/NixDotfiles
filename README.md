# NixDotfiles

NixOS (flake) + Home Manager configuration for host `nixos`, user `mc`.
GNOME desktop with the Orchis theme, fish + Ghostty, fully declarative.

## Layout

| Path | What it holds |
|---|---|
| `flake.nix` / `flake.lock` | Inputs (nixpkgs 26.05, Home Manager, Lanzaboote, Spicetify, Helium, Orchis, nix-flatpak) and the `nixos` system |
| `configuration.nix` | System: boot (Lanzaboote + TPM2 LUKS), hardware, networking, GNOME/GDM, audio, services, system packages and GNOME extensions |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`; don't edit |
| `home.nix` | User packages, GTK theme (Orchis), icons (Tela), cursor (Bibata), Spicetify |
| `modules/gnome.nix` | Every GNOME setting (dconf): Settings app, shortcuts, extension settings; plus wallpaper, display layout, default apps and the login/logout sound service |
| `modules/maximize-to-tile.nix` | Builds + installs the custom "Maximize To Tile" GNOME Shell extension (source in `extras/gnome-extensions/`); enabled and configured from `modules/gnome.nix` like any other extension |
| `modules/shell.nix` | fish (with the oh-my-zsh git aliases as abbreviations), Starship, Ghostty |
| `modules/fastfetch.nix` | fastfetch |
| `extras/` | Files the config installs: wallpaper, `monitors.xml`, sound theme, fastfetch config, Nautilus file templates (`templates/`), the custom `maximize-to-tile` extension's source (`gnome-extensions/`) |

## Rebuild

```sh
sudo nixos-rebuild switch --flake .#nixos   # or `boot` to apply on next boot
```

New files must be `git add`ed before building (flakes only see tracked files).

## Changing a GNOME setting

Settings made in the GNOME UI live in dconf and are re-applied from
`modules/gnome.nix` on every rebuild, so a setting only sticks once it is written
there. To capture a change you made in the UI:

```sh
dconf watch /          # shows the key and value as you change it
dconf dump /org/gnome/shell/extensions/dash-to-dock/   # or dump a whole extension
```

Then add the key to the matching section in `modules/gnome.nix`.

Deliberately **not** stored: device pairing (GSConnect), saved Weather locations,
window sizes/history, and anything holding secrets.

## Notes

- The Orchis theme is built from upstream (`orchis-src` input); update it with
  `nix flake update orchis-src`. Change the colour by editing `orchisTheme` in `home.nix`.
- GNOME extensions are installed in `configuration.nix` and switched on in
  `modules/gnome.nix` (`enabled-extensions`); add a package there when enabling a new one.
- `maximize-to-tile@local` (`modules/maximize-to-tile.nix`, source in
  `extras/gnome-extensions/`) is a custom extension, not from nixpkgs. GNOME gives
  extensions no hook on the titlebar maximize button itself (it's handled inside each
  app's own client-side decoration), so it reacts to the resulting window-maximized
  state instead and resizes the window to the work area with a gap, so the button,
  double-click-titlebar, keybindings and the window menu all end up looking like
  Tiling Shell's own top-edge-drag tiling instead of a true edge-to-edge maximize.
  Gap size: `org/gnome/shell/extensions/maximize-to-tile` → `gap` in `modules/gnome.nix`.
- Flatpaks are declarative (`services.flatpak` in `configuration.nix`, via the `nix-flatpak`
  input): the app list there is the full source of truth, kept in sync on every rebuild.
  `uninstallUnmanaged = true` means any app installed by hand with `flatpak install` gets
  removed on the next `nixos-rebuild switch` — add it to `services.flatpak.packages` instead
  of running `flatpak install` directly. `flathub` is the only remote.
- GNOME dropped native login/logout sounds years ago; `modules/gnome.nix` recreates them
  with a `systemd.user` service (`login-logout-sound`) that plays `desktop-login` on start
  and `desktop-logout` on `ExecStop`. It depends on `pipewire`/`wireplumber` so audio is
  still alive when it stops. One side effect: since it's a normal systemd user unit,
  `home-manager switch` restarts it mid-session, so you'll hear logout+login play back to
  back on every rebuild, not just on an actual login/logout.
- Minecraft Bedrock comes from the `bedrock-on-linux` input. It deliberately does **not**
  follow our nixpkgs: it is written for nixos-unstable and fails to evaluate on 26.05.
  Update it with `nix flake update bedrock-on-linux`.
- Right-click → New Document in Files lists the files in `extras/templates/` (copied to
  `~/Templates` on every rebuild; copied rather than symlinked so new files are writable).
  Add a file there to add a template.
- Monitor brightness sliders use DDC/CI (`ddcutil`); the monitor must have DDC/CI enabled
  in its on-screen menu.
- `extras/monitors.xml` is copied to `~/.config/monitors.xml` on activation (and used by
  GDM), so the display layout resets to the repo's version on each rebuild.
