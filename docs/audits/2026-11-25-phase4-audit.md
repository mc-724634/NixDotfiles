## D. Hyprland audit

Effective Hyprland version: **0.55.4** (RUNTIME, `hyprctl version`) — this
matters because `animations.lua` contains an explicit version gate
(`local minor = tonumber(hl.version():match("^0%.(%d+)")); if not minor or
minor >= 56 then ...`) disabling `shadowangle`/`glowangle` animation leaves on
Hyprland ≥0.56. **Confirmed this pass**: at 0.55.4, that branch does **not**
fire, so those two leaves are left at Hyprland's own default (unset, i.e.
whatever the base animation inherits) — this is correct, version-aware
behavior already working as designed, not a bug.

**Confirmed, traced interaction (new finding this pass)**: `hyprland.lua`
itself declares `general.gaps_in = 5`, `general.gaps_out = 5`,
`decoration.rounding = 12` in its own inline `hl.config()` call. Its
`require()` chain then loads `dms.layout`, which declares
`general.gaps_in = 4`, `general.gaps_out = 4`, `decoration.rounding = 16`,
`decoration.blur.passes = 2`, `general.resize_on_border = false`. Since Lua
`require()`s run sequentially and each `hl.config()` call mutates the same
live compositor state, **the later call wins per-key**. Verified live, not
just reasoned about: `hyprctl getoption general:gaps_in` → `4`,
`general:gaps_out` → `4`, `decoration:rounding` → `16`,
`decoration:blur:passes` → `2`, `general:resize_on_border` → `false`. **This
means `hyprland.lua`'s own gaps/rounding values (5/5/12) are dead — anyone
editing those three lines expecting a visual change would see nothing,
because `dms/layout.lua` (loaded later, and the file DMS's own `dms deploy`
regenerates) always wins.** Not a defect to fix — `layout.lua` is correctly
the file that should own these per the documented "DMS live-edits several of
these files" design — but a genuinely useful fact that wasn't previously
written down anywhere, and is exactly the kind of "trace the actual effect,
don't just read the declaration" finding this phase asked for.

**Window/layer rules**: cross-checked every `hl.window_rule`/`hl.layer_rule`
across `hyprland.lua`, `layout.lua`, and `windowrules.lua` for class-regex
correctness and for duplicate/conflicting rules on the same class. Found:
`hyprland.lua` and `layout.lua` **both** declare the identical pair of layer
rules (`namespace = "^(quickshell)$"` and `"^dms:.*"`, both `no_anim = true`)
— harmless (declaring the same layer rule twice is a no-op, not a conflict),
but genuinely redundant. No conflicting rules (same class, different outcome)
were found anywhere.

**Input**: `hyprland.lua`'s inline `follow_mouse = 0` is overridden by

**Cursor — the one genuinely open thread from this pass**: `dms/cursor.lua`
is empty (header comment only — confirmed by direct read, DMS has never
written anything into it). Despite this, cursor theming is **demonstrably
working for Hyprland-direct-spawned clients**: `ghostty`'s live process
environment (`/proc/<pid>/environ`, a running instance, PID 3339) shows
`XCURSOR_THEME=Bibata-Modern-Classic`, `XCURSOR_SIZE=24` — correct, and
matching `dconf read .../cursor-theme`. Neither Hyprland's config files nor
any `hl.env()` call anywhere in this repo sets these — Hyprland 0.55.4
apparently derives and exports them itself (most likely from the GSettings
cursor-theme/size this session already has set, a documented newer-Hyprland
auto-detection behavior, **not independently confirmed from Hyprland's own
source this pass** — flagged as DOC-unconfirmed, inferred from behavior only).
However: `UWSM_FINALIZE_VARNAMES` (visible in `systemctl --user
show-environment`) explicitly lists `XCURSOR_THEME`/`XCURSOR_SIZE` as
variables UWSM intends to sync into the systemd user-manager environment —
and **they are absent from that environment block** (confirmed via the full,
untruncated `systemctl --user show-environment` dump, and independently
re-confirmed by reading DMS's actual process environment directly, which also
lacks them). **Practical consequence, honestly assessed**: GTK apps are
unaffected (they resolve cursor via `gtk-cursor-theme-name` in
`settings.ini`, confirmed correctly patched). Native-Wayland clients using the
`cursor-shape-v1` protocol are also unaffected (the compositor supplies the
cursor directly, no client-side env var needed) — and DMS/Quickshell, being a
modern Qt6/Wayland client, almost certainly falls into this category, which is
likely *why* no visible cursor glitch has ever been reported for DMS's own
UI. The residual risk is narrower than it first looks: **any XWayland or
Wayland client that reads `XCURSOR_THEME` directly and does *not* implement
`cursor-shape-v1`, and that is launched as a systemd user service (not
Hyprland-direct-spawned) would show a fallback cursor instead of Bibata.**
No such app was identified as actually installed in this config (everything
in `home.packages` is either GTK, Qt-via-qtct, or Hyprland-direct-launched).
**Marked UNRESOLVED, not fixed**: this is exactly the kind of thing the phase
asked to surface rather than hide, but inventing a fix for a consequence that
cannot be shown to affect any installed app would be exactly the "invented
defect" the instructions explicitly forbid.

**Fonts**: `hack-font` (Ghostty) and `noto-fonts` are the only two declared

## M. Findings

### Finding 1 — README.md contains stale, now-incorrect documentation (confirmed defect, safe to fix)
**Existing behavior**: `README.md` lines 85-90 state DMS is "started via
`hl.exec_cmd("dms run")` in `hyprland.lua`'s startup hook, not via
`programs.dank-material-shell.systemd.enable` (left off)."
**Evidence it's wrong**: `configuration.nix:201` has `systemd.enable = true;`
with an explicit comment confirming the switch; `hyprland.lua`'s
`DMS_STARTUP` block (read in full this pass) contains **no** `dms run` exec
line at all, only env-var setting, with its own comment confirming the hook
was deliberately removed to avoid a double-launch race.
**Proposed fix**: update README.md to describe the current systemd-service-
based launch, matching what `configuration.nix`/`hyprland.lua` actually do.
**Risk**: none — documentation-only, zero effect on system behavior.
**Rollback**: trivial `git revert`/`git diff` on one file.
**Status**: fix applied this pass (see Final Validation).

### Finding 2 — Three dead `hl.unbind()` calls in `binds-user.lua` (confirmed, cosmetic only)
**Evidence**: `hl.unbind("SUPER + CTRL + space")`, one of the `SUPER + W`-
adjacent unbinds, and one `SUPER + ALT + space`-adjacent unbind each target a
key combination that was never bound in `binds.lua` in the first place
(confirmed by grepping every `.lua` file in the repo for each exact key
combination string). Unbinding a non-existent bind is a harmless no-op in
Hyprland's Lua API (consistent with every other call in the file succeeding on
rebuild with no errors).
**Proposed fix**: none applied — removing a few harmless lines carries zero
functional benefit and isn't worth a diff on a file DMS's own keybind editor
can rewrite wholesale anyway. Documented, not changed.
**Status**: left as-is, by design (see Unchanged Settings below).

### Finding 3 — XCURSOR_THEME/SIZE not finalized into the systemd user environment (confirmed, no demonstrated impact)
Covered in full in §F. **Not fixed**: no installed application was identified
that would actually be affected (GTK apps use `settings.ini`; DMS/Quickshell
very likely uses `cursor-shape-v1`). Recorded as a genuine architectural gap
worth knowing about, explicitly not "fixed" with a speculative `hl.env()`
addition that has no confirmed problem to solve.
